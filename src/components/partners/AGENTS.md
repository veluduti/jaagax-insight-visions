- Brands reuse `partner_businesses.brand_settings` and independent `partner_hotels.brand_id`; atomic owner-authorized actions apply approved policy defaults while preserving property groups, overrides, supplier conditions and bookings.
- Hotel partner pages use the shared workspace layout and validated owner-property context so switching properties updates every editor.
- Load and save setup through hospitality services using existing `partner_hotels.policies` and `type_details`; do not create parallel property inventories.
- Portfolio analytics use owner-scoped hospitality services and calendar reservations, keep currencies separate, and reuse partner accounts/businesses plus property metadata for groups and brands so individual dashboards share the same records.
- Calendar counts mirror `room_free_units` through shared inventory rules, including legacy capacity and maintenance units; unit mutations lock the reservation room to prevent races without modifying bookings.
- Property setup uses one owner-authorized atomic RPC and linked existing application/payout records; administrator approval updates the linked hotel instead of importing duplicate inventory, and property applications never replace account onboarding gates.
- Property groups are `partner_businesses` rows with settings in `group_settings`; group team roles grant access through existing `hotel_staff` rows on each group property, and group activity is `hospitality_audit_log` entity `property_group`.
- OTA, PMS and channel-manager connections use the shared integration service and central hotel/room/rate/booking records; credentials remain encrypted server-side, live activation requires a successful test and Global Admin approval, and provider-specific adapters must not bypass inventory or settlement safeguards.
- Residents, Guests & Leads (`/partners/residents`) derives people from existing long stays, bookings, invoices and waitlist via `residentsService.ts`; only enquiries live in `hotel_leads`, and wording/tabs/lead stages come from `src/config/residentModes.ts` so one screen serves every property type.
